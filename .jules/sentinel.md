## 2026-03-05 - Safe Error Handling and Input Validation in Express API Endpoints
**Vulnerability:** Raw error message leakage (e.g. `error.message`) in Express catch blocks when invoking external APIs (such as the Google Gemini GenAI API), alongside a lack of type and bounds validation on incoming client payloads. This could expose internal API key formats, Downstream/Upstream stack traces, or other sensitive diagnostic details.
**Learning:** Concatenating `error.message` directly in JSON response payloads leaks diagnostic context of third-party dependencies, leading to an information disclosure risk. Input validation was also missing on request parameters (`subject`, `topicKeyword`, `text`, `numQuestions`, `grade`), permitting potentially malformed queries.
**Prevention:** Always sanitize Express API `catch` blocks to return generic, secure messages to clients while logging full traces internally. Implement type-checking and length/bounds validation middleware or helper utilities (such as `validateString` and `validateInteger`) on all incoming POST requests.
