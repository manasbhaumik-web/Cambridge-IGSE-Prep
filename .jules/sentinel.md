## 2026-03-05 - Secure API Input Validation and Diagnostic Leak Prevention in AI Endpoints
**Vulnerability:** Unsanitized user-supplied parameters to Google Gemini AI API endpoints (such as `subject`, `topic`, `difficulty`, `message`, `grade`, etc.) could lead to API misuse, prompt injection, or performance issues. Furthermore, internal raw exception details/stack traces were being leaked back to clients inside the HTTP 500 error responses, enabling directory structure and stack fingerprinting.
**Learning:** The endpoints directly processed input bodies without schema definition, bounds checking, or type enforcement, and used string formatting in AI prompts. Express routes had generic try-catch blocks that concatenated raw `error.message` directly in client responses, missing security boundaries for client-side vs server-side failures.
**Prevention:** Enforce a custom `ValidationError` class to distinguish client validation errors (HTTP 400 with a descriptive field failure message) from unexpected internal errors. Implement helper functions `validateString` and `validateInteger` to strictly validate types, ranges, and string lengths before invoking downstream AI pipelines. Capture any unhandled errors within route handlers internally and return generic, non-disclosing messages (HTTP 500) to clients.
