## 2026-03-04 - [Input Validation and Error Exposure in API Endpoints]
**Vulnerability:** Lack of server-side input validation on Gemini-integrated endpoints allowed potential malformed or overly large payloads to bypass checks. Additionally, backend exception stack traces and developer-level error messages (such as "Failed to generate question: " + error.message) were returned directly to clients, leading to diagnostic details leakage.
**Learning:** In a sandbox-heavy application with AI client generation, input constraints are easily overlooked since frontends normally send well-formed payloads. However, direct endpoint requests could cause unhandled exceptions or run up large token costs. Leaving raw backend details exposed also compromises security posture.
**Prevention:** Always validate all types, lengths, and bounds for user-supplied string and integer fields, and separate client-side validation errors (returning HTTP 400 with descriptive explanations) from unexpected system/API errors (logged internally and returned as clean, non-descriptive HTTP 500 error messages).
